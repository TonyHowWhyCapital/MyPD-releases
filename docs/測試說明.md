# MyPD 1.2.5 測試說明

這份文件給參與 MyPD 第一輪內部測試的同事。它說明這一版要測什麼、建議的測試順序、已知問題，以及回報問題時需要附上的資訊。

- 安裝與 Java 設定：請看 [安裝手冊](安裝手冊.md)。
- 功能操作：請看 [操作手冊](操作手冊.md) 與 [操作手冊：進階工具與參考](操作手冊-進階工具.md)。

## 1. 測試前請注意

- **先備份。** 請用複本測試，不要直接拿正式的專案檔案或 PDM 檔案來試。MyPD 會直接改寫您開啟的 PDM 檔案（第一次修改前會留一份 `.pdm.bak`）。
- **資料庫請用測試環境。** MyPD 只在兩種情況會更改資料庫：在「模型比較與合併」按「執行到資料庫」並確認後，會執行 ALTER 指令碼；在「產生測試資料」選「直接寫入資料庫」並確認後，會寫入資料。其他功能只讀取資料庫結構。產生的 SQL 要不要執行、在哪裡執行，由您決定，請不要在正式環境試跑。
- **專案檔案含連線密碼。** 資料庫連線的帳號與密碼存在專案檔案中。回報問題要附專案檔案時，請先刪除連線或改用測試帳號。
- **MyPD 不連網。** 程式不會自動更新，也不會回傳任何資料。新版本會另外發放安裝檔。

測試時請特別留意三件事：

1. **資料有沒有遺失或被改壞。** 儲存、關閉、再開啟之後，內容是否與儲存前相同。PDM 檔案寫回後，原本的工具是否還能正常開啟。
2. **產生的 SQL 是否正確。** 建表、索引、唯一約束、備註與增量 DDL 能否在目標資料庫執行。
3. **介面文字是否看得懂。** 簡體字、對岸用語、錯字、英文殘留、文字被截斷。

## 3. 已知問題

下列問題已經知道，不需要重複回報。

| 編號 | 問題 | 暫時的做法 |
|------|------|------------|
| K01 | 「模型比較與合併」選「資料庫」時，連線下拉清單顯示的是內部代碼，不是連線名稱 | 清單順序與「資料庫連線設定」相同，依順序辨認 |
| K02 | 「模型比較與合併」的「專案檔案」與報表的「新增模型檔案」不能讀取 `.pdm` 檔案 | 先開啟 PDM，「另存為」`.pdma.json` 後再使用 |
| K03 | 儲存 PDM 時的確認文字說關係線與關係圖版面配置不會寫入，實際上會寫入 | 以操作手冊 5.2 節的表格為準 |
| K04 | 新專案的預設欄位顯示名稱是簡體字（租户号、乐观锁等） | 到「設定」→「表設定」→「預設欄位」修改 |
| K05 | 部分介面文字有錯字：「連線名不能重複或者為為空」 | 不影響功能 |
| K06 | 安裝檔沒有 Apple 公證與 Windows 程式碼簽章，第一次開啟會出現系統警告 | 依安裝手冊 3.2 節與第 4 節放行 |

## 4. 如何回報問題

請把問題回報給本次測試的負責人。每一個問題請分開回報，並附上下列資訊：

| 項目 | 說明 | 範例 |
|------|------|------|
| 測試項目 | 第 2 節的編號 | T10 |
| 環境 | 作業系統與版本、Mac 的晶片、Java 版本 | macOS 15.3，Apple M2，Java 17.0.13 |
| 資料庫 | 與資料庫有關時，寫出資料庫類型與版本 | SQL Server 2019 |
| 操作步驟 | 從開啟專案開始，一步一步寫出做了什麼 | 開啟 a.pdm，在 ORDERS 表新增欄位 NOTE，按「儲存」 |
| 預期結果 | 您認為應該發生什麼 | 欄位寫入 a.pdm |
| 實際結果 | 實際發生什麼，含完整的錯誤訊息 | 顯示「儲存失敗」與下列訊息 |
| 附件 | 螢幕截圖、可重現問題的專案檔案或 PDM 檔案、產生的 SQL | |

錯誤對話框提到記錄檔時，請一併附上對話框所指資料夾中的記錄檔。

嚴重程度請依下表判斷：

| 等級 | 定義 |
|------|------|
| 嚴重 | 資料遺失、檔案損毀、程式當掉、產生的 SQL 會破壞資料 |
| 一般 | 功能無法完成或結果錯誤，但有其他做法可以繞過 |
| 輕微 | 文字、排版、外觀問題，或操作不順手 |

功能建議也歡迎提出，請與問題分開，並說明您想完成的工作。

## 5. 程式當掉或資料異常時

- 視窗當掉或沒有回應時，MyPD 會在專案資料夾寫出 `<專案名>-backup-<時間>.chnr.json`。請保留這個檔案並附在回報中。
- 專案內容被改壞時，可以用工具列的「操作歷史」恢復到先前儲存的快照，請看操作手冊 7.7 節。
- PDM 檔案的原始內容保留在同目錄的 `<檔名>.pdm.bak`。
